# منصة الأنشطة التفاعلية للتدريب — SAFE
**Interactive Training Activities Platform**

منصة للمدرب لإدارة الدورات والأنشطة والأسئلة التفاعلية وتشغيلها مباشرةً في التدريب الحضوري وعن بُعد، مع استقبال إجابات المتدربين لحظياً وتقارير قابلة للتصدير.

## التشغيل السريع

```bash
npm install
npm run build
npm start            # http://localhost:3000
```
عند أول فتح تظهر صفحة **إعداد حساب المدرب الأول**. بعد إنشائه تُغلق هذه الصفحة نهائياً، ويمكن إضافة مدربين آخرين من «الإعدادات».

للتطوير: `npm run dev`

### متغيرات البيئة (انظر `.env.example`)
| المتغير | الوصف |
|---|---|
| `DATA_DIR` | مجلد قاعدة البيانات والصور المرفوعة (الافتراضي `./data`). اجعله على تخزين دائم. |
| `COOKIE_SECURE` | اجعلها `true` عند التشغيل خلف HTTPS. |
| `PORT` | منفذ الخادم. |
| `TRUST_PROXY` | اجعلها `true` فقط خلف Nginx/Proxy يضبط `X-Real-IP`، ليُحسب حدّ المحاولات لكل عنوان IP. |

## النشر
- تعمل المنصة كخادم Node.js واحد (`npm start`) على أي VPS أو حاوية Docker أو خدمة تدعم Node (مثل Render / Railway / Fly.io) مع **قرص دائم** لمجلد `DATA_DIR`.
- خلف Nginx: عطّل التخزين المؤقت لمسارات البث المباشر:
  ```nginx
  location ~ /stream$ { proxy_pass http://127.0.0.1:3000; proxy_buffering off; proxy_read_timeout 1h; }
  ```
- ليست مناسبة لبيئات Serverless (مثل Vercel) لأن التحديث اللحظي يعتمد على اتصال مستمر وعلى عملية خادم واحدة.
- النسخ الاحتياطي: انسخ ملف `data/platform.db` (ومجلد `data/uploads`).

## التقنيات
Next.js 16 (App Router) · TypeScript · Tailwind CSS 4 · SQLite (better-sqlite3, WAL) · Server-Sent Events للتحديث اللحظي · ExcelJS للتصدير.

تم اختيار SQLite + SSE بدلاً من Supabase لأنها تعمل وتُختبر بالكامل دون خدمات خارجية. كل استعلامات قاعدة البيانات معزولة في `src/lib/repo.ts` و`live.ts` و`reports.ts`، وقناة البث في `src/lib/bus.ts`، فيمكن لاحقاً نقلها إلى PostgreSQL/Supabase (واستبدال الناقل بـ Supabase Realtime أو LISTEN/NOTIFY) دون تغيير الواجهات.

## الصلاحيات (مطبّقة في الخادم)
- **المدرب**: جلسة آمنة (ملف تعريف ارتباط httpOnly، كلمات مرور scrypt، حدّ لمحاولات الدخول، تحقق من مصدر الطلب). كل استعلام مقيّد بمعرّف المدرب، فلا يرى مدرب بيانات مدرب آخر.
- **المتدرب**: رمز خاص بتشغيل واحد فقط من النشاط. لا يستقبل الإجابة الصحيحة أو الشرح إلا بعد أن يكشفها المدرب، وإذا كان الإظهار مفعّلاً. لا يصله أي شيء عن إجابات غيره. تُرفض الإجابة إذا كان السؤال غير مفتوح أو انتهى وقته، ولا تُعدّل بعد الإغلاق إلا إذا سمح المدرب، ولا تُقبل أبداً بعد كشف النتيجة.
- **قناة البث** ترسل إشارة «تغيّر» فقط، ثم يطلب كل طرف حالته من الخادم بعد التحقق من صلاحياته.

## ملاحظات
- **تصدير PDF** يفتح نسخة التقرير المهيّأة للطباعة، ثم تُحفظ من نافذة الطباعة باختيار «حفظ كـ PDF». هذا يحافظ على تشكيل الخط العربي بشكل صحيح.
- **إعادة تشغيل النشاط** تنشئ «تشغيلاً» جديداً بمشاركين جدد، وتبقى نتائج التشغيلات السابقة متاحة في التقارير.

## وضع العرض (Presenter Mode) — `/present/<رقم النشاط>`
شاشة مخصصة للبروجكتر أو لمشاركة الشاشة في التدريب عن بُعد:
- السؤال بخط كبير، والخيارات في بطاقات، ومؤقت تنازلي دائري، وعدد المشاركين وعدد من أرسلوا إجاباتهم مع شريط تقدّم يتحدث لحظياً.
- شريط تحكم على الشاشة يختفي تلقائياً عند عدم تحريك الفأرة: بدء السؤال، إغلاق الإجابات، +15 ثانية، توزيع الإجابات (إظهار/إخفاء)، إظهار الإجابة الصحيحة، السابق/التالي، إنهاء النشاط، رمز الانضمام، ملء الشاشة.
- مراحل السؤال كلها بيد المدرب: جاهز ← استقبال الإجابات ← مغلق ← الإجابة الصحيحة.
- **حماية الإجابة**: الشاشة تقرأ من `/api/activities/:id/present`، ولا يرسل الخادم الإجابة الصحيحة أو الشرح أو الإجابات المقبولة قبل أن يكشفها المدرب. خطوات أسئلة الترتيب تُعرض مخلوطة، ولا تُرسل أسماء المتدربين أو إجاباتهم الفردية. يستطيع المدرب عرض نسب التوزيع قبل الكشف دون تمييز الخيار الصحيح.
- الاختصارات: المسافة/Enter = الخطوة التالية في مرحلة السؤال، D = التوزيع، R = الإجابة الصحيحة، الأسهم = التنقل، Q = رمز الانضمام، F = ملء الشاشة.

## واجهة المتدرب (للجوال)
- الدخول بمسح QR (يفتح `/play/<الرمز>` مباشرة) أو بإدخال الرمز في `/join`، ويمكن تمرير الرمز في الرابط: `/join?code=123456`.
- يطلب النموذج البيانات حسب إعداد النشاط (الاسم فقط، أو الاسم ورقم المتدرب)، ويحفظها على الجهاز لتسهيل الدخول في المرات التالية.
- يظهر السؤال الحالي فقط بأزرار كبيرة، وزر الإرسال مثبت أسفل الشاشة. بعد الإرسال تظهر رسالة تأكيد مع الإجابة المرسلة.
- حالات الانتظار: قبل بدء النشاط، وقبل السؤال الأول، و«بانتظار السؤال التالي». كما يظهر تنبيه عند انقطاع الاتصال، وتبقى الشاشة مضاءة أثناء النشاط.
- **إجابة واحدة** هي الإعداد الافتراضي. يمكن تفعيل «السماح بتغيير الإجابة قبل إغلاق السؤال» من إعدادات النشاط. المنع مطبّق في قاعدة البيانات بشكل ذرّي، فالضغط المزدوج أو الطلبات المتوازية لا تسجّل إلا إجابة واحدة.
- حماية المتدرب:
  - رمز المتدرب في ملف تعريف ارتباط httpOnly محصور في `/api/play` ومرتبط بتشغيل واحد.
  - الحقول المرسلة إلى المتدرب محددة بقائمة بيضاء.
  - محاولات تخمين رموز الأنشطة محدودة العدد.
  - الصفحات محمية بترويسات أمان (CSP و frame-ancestors و nosniff).

## مكتبة الأسئلة المركزية — `/library`
قاعدة معرفية خاصة بكل مدرب تستخدمها جميع دوراته:
- **التصنيف:** المجال › التخصص › الموضوع، مع مستوى الصعوبة ووسوم متعددة لكل سؤال. تظهر للقيم المستخدمة سابقاً اقتراحات تلقائية.
- **البحث:** بعنوان السؤال أو نصه أو خياراته أو وسومه. يتجاهل البحث فروق الهمزات والتاء المربوطة والتشكيل، ويجب أن تطابق كل الكلمات. يمكن الجمع بين البحث وفلاتر المجال والتخصص والموضوع والصعوبة والنوع والوسوم، ويُحفظ ذلك كله في رابط الصفحة.
- **الاستيراد:** تحديد سؤال أو أكثر واستيرادها إلى نشاط موجود في أي دورة أو إلى نشاط جديد. ويمكن الاستيراد أيضاً من داخل صفحة النشاط عبر «استيراد من المكتبة».
- **الحفظ في المكتبة:** يُحفظ أي سؤال كُتب داخل نشاط بزر «حفظ في المكتبة»، أو تُحفظ كل أسئلة النشاط دفعة واحدة.
- **الإصدارات:** النشاط يحتفظ بنسخة مرتبطة من السؤال. تعديل سؤال المكتبة ينشئ إصداراً جديداً ولا يغيّر الأنشطة. تظهر في النشاط علامة «تحديث متاح»، والتحديث يتم بقرار المدرب.
- **حماية السجلات:** عند فتح أي سؤال في التشغيل تُحفظ لقطة منه كما طُرح، والتقارير والتصدير وإعادة التصحيح تعتمد على هذه اللقطة. لذلك لا يغيّر تعديل السؤال أو حذفه لاحقاً أي إجابات أو نتائج سابقة. السؤال الذي سبق طرحه يُخفى عند حذفه ولا يُمحى.
- **الأرشفة:** الأسئلة القديمة تُؤرشف فتختفي من البحث والاستيراد، ويمكن استعادتها. لا يُسمح بحذف سؤال مستخدم في أنشطة، والبديل أرشفته.
- عمليات جماعية: استيراد، إضافة وسم، أرشفة واستعادة.
